# Dimensy patches for Frappe Helpdesk

Base: Helpdesk v1.30.1 (branch `release/1.30`). One commit per patch, written as [Conventional Commits](https://www.conventionalcommits.org/) with a `Dimensy-Patch: Pn` trailer (find them with `git log --grep "Dimensy-Patch"`). Plan: `docs/patch-plan.md` in the Dimensy project repository.

| # | Commit | Files | Purpose |
|---|---|---|---|
| P1 | `fix(api): hide internal ticket data from non-agents` | `helpdesk/utils.py`, `helpdesk/helpdesk/doctype/hd_ticket/api.py`, `test_hd_ticket.py` | `get_one` drops `INTERNAL_TICKET_FIELDS` (priority, team, SLA fields, `_assign`, `_comments`, ...) for non-agents. `get_communications` replaces the sender of agent replies with a team name (site config `helpdesk_customer_agent_name`, default "Support Team") and drops `bcc`. Decided on the server from the user's role, not from a client parameter. Agent behavior is unchanged. Test: `test_get_one_hides_internal_data_from_non_agents`. |
| P2 | `fix(api): strip internal columns from the customer ticket list` | `helpdesk/api/doc.py`, `test_hd_ticket.py` | `get_list_data`, `sort_options` and `get_quick_filters` force portal mode for non-agents. Columns, rows and data requested by the client are filtered with `INTERNAL_TICKET_FIELDS`. Portal field lists no longer include `priority`, `response_by` or `resolution_by`. Test: `test_get_list_data_hides_internal_columns_from_non_agents`. |
| P3 | `fix(portal): remove Team, Priority and SLA from the customer ticket sidebar` | `desk/src/components/ticket/TicketCustomerSidebar.vue` | Removes the Team and Priority rows and the SLA block (First Response, Resolution) from the portal customer sidebar, together with the now-unused SLA imports and computations. Test: Playwright (customer, desktop and mobile). |
| P4 | `chore(ui): rebrand the help panel to Dimensy Helpdesk` | `desk/src/components/layouts/Sidebar.vue` | Help/onboarding panel title "Frappe Helpdesk" becomes "Dimensy Helpdesk". |
| P5 | `fix(ui): show the full user name from the server` | `desk/src/stores/user.ts` | `full_name` from `get_users` is no longer overwritten by the email prefix ("Cs1"); assignee names in the chip and dropdown follow the User data. |
| P6 | `fix(ui): do not load HD Agent Status for customers` | `desk/src/stores/agentStatus.ts` | The agent status list is only fetched for sessions that have an HD Agent record, which removes the "Insufficient Permission for HD Agent Status" toast on the customer mobile view. Side effect: accounts without an HD Agent record (e.g. admin) do not see agent presence dots. |
| P7 | `feat(portal): link to the source code in the customer sidebar` | `helpdesk/www/helpdesk/index.py`, `desk/src/types.ts`, `desk/src/components/layouts/Sidebar.vue` | AGPL section 13: customers of the modified portal get a visible "Source code" link. The URL comes from the site config `helpdesk_source_code_url` through the boot context; the link is hidden when it is empty and for agents. |
| P8 | `fix(api): hide ticket type and custom fields from non-agents` | `helpdesk/utils.py`, `helpdesk/helpdesk/doctype/hd_ticket/api.py`, `helpdesk/api/doc.py`, `test_hd_ticket.py` | `ticket_type` joins `INTERNAL_TICKET_FIELDS`, and the new `is_internal_ticket_field` also treats every `custom_*` field as internal (Dimensy adds channel, platform and contact email for agents). Used by `get_one`, the customer ticket list (rows and columns) and the filter field metadata. A custom field meant for customers has to be exposed deliberately. Test: `test_is_internal_ticket_field_covers_type_and_custom_fields`. |
| P9 | `fix(ui): keep the help panel closed on page load` | `desk/src/components/layouts/Sidebar.vue` | frappe-ui `setUp` opens the help panel on every load for managers before the onboarding status is known, so it covered the ticket sidebar even with onboarding complete. The panel now opens only from the banner or the Cmd/Ctrl+H shortcut. |
| P10 | `fix(api): block customers from querying internal ticket data through the generic API` | `helpdesk/utils.py`, `helpdesk/hooks.py`, `test_hd_ticket.py` | `before_request` hook `restrict_internal_ticket_access`: for non-agents querying HD Ticket it drops internal fields from `fields`/`fieldname` and refuses `filters`, `or_filters`, `order_by` and `group_by` that mention them. Frappe always includes `_assign`/`_comments` and lets clients filter and sort by any readable column, so field-level permissions alone leave a leak and an oracle. `is_internal_ticket_field` now normalises client expressions (aliases, `tabHD Ticket.` prefixes, case) and treats anything that is not a bare field name as internal. Pairs with field-level permissions set by `scripts/security.py` in the Dimensy project. Test: `test_is_internal_ticket_field_covers_type_and_custom_fields` and `scripts/test_security.py` (API paths). |
| P11 | `fix(api): vet decoded query parameters and fail closed` | `helpdesk/utils.py`, `scripts/test_security.py` (Dimensy project) | Hardens P10 after security review. Filters, `or_filters`, `order_by` and `group_by` are decoded before the check (a raw-text scan missed JSON escapes such as `\u0070riority`); the doctype is resolved from the REST v1 and v2 paths, case-insensitively; `pluck`, `field` and `group_by_field` are treated like `fields`; shapes that cannot be vetted are replaced with `name` instead of passing through. |
| P12 | `fix(api): restrict knowledge base articles to Public categories for non-agents` | `helpdesk/helpdesk/doctype/hd_article_category/` (new `visibility` field Public/Internal, default Internal), `hd_article/hd_article.py`, `hooks.py`, `helpdesk/api/knowledge_base.py`, `helpdesk/api/article.py` | `HD Customer` and `HD Customer Manager` could read every article, Draft included, through the generic REST API. `permission_query_conditions` and `has_permission` now limit non-agents to Published articles in Public categories (and Public categories only). `get_article` checks read permission instead of only the status, and the article suggestions used on the new-ticket page drop Internal results from the search index. Test: `scripts/test_security.py` (Dimensy project). |
| P13 | `feat(portal): add a public help center at /help` | `helpdesk/www/help/`, `hooks.py` | Server-rendered category list, article list and article page that need no login, so links in email replies work for people without a portal account. Shows only Published articles of Public categories (404 otherwise); article HTML is sanitised. Always light, styled after dimensy.id (SUSE headings, Inter body, blue gradient pill button, grid motif) with a "Buat Tiket" button to the ticket dashboard and the official support contacts (email, WhatsApp, phone; hardcoded in the template) under every article and in the footer; no Source code link (the AGPL link stays in the portal sidebar, P7). Client-side title search on the home page, "General" shown as "Informasi Umum" and listed first, then categories alphabetically. Logo from site config `helpdesk_help_logo`. The portal router is not touched. |
| P14 | `feat(kb): mark Internal categories and guard them in the agent knowledge base` | `desk/src/pages/knowledge-base/KnowledgeBaseAgent.vue`, `desk/src/components/ListViewBuilder.vue`, `desk/src/components/knowledge-base/CategoryModal.vue`, `desk/src/stores/knowledgeBase.ts`, `helpdesk/api/knowledge_base.py`, `helpdesk/api/doc.py`, `hd_article_category.py` | The category list marks Internal categories ("· Internal"); the create and edit dialogs have a Visibility select; Share copies the `/help/<id>` link (Public only; it used to copy the old `kb-public` link). Server guards: an Internal category that still has articles cannot be deleted (the fallback would move them to the Public General category), and moving or merging Internal articles into a Public category needs `confirm_public` (the UI asks for confirmation). The confirmation also covers the Move To action on the article page (first version only handled the list page). Test: `scripts/test_security.py` and a Playwright run of the dialog. |
